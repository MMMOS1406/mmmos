SIMPLEST IMPLEMENTATION DESIGN (after verification; existing MMMOS infrastructure only)
VA flow:
  approved song -> "Generate music" -> listen to Suno's versions in MMMOS
  -> "Use this version" / "Regenerate" / "Upload MP3 myself"
  -> MMMOS stores the original MP3 -> the existing Build continues.
Server (api/ops.js, one new SRV Studio-only action srv_studio_v2_music):
- Gates: VA/CEO session, existing publish gate, V2 flag, and its own flag
  app_settings.srv_studio_v2_music.enabled (default OFF).
- Operations:
  - connect: OAuth PKCE start and finish. The CEO consents once; the refresh token is
    sealed (AES-256-GCM, as for the Mix upload session).
  - generate: reads the package's APPROVED lyrics and style (approval hash checked) and
    calls the connector's generate tool with exactly that text. It records song IDs and
    shows the credits used.
  - status: lists the versions with listen links.
  - select: downloads the chosen version through the official download tool, checks it
    (MP3, duration 2:00-7:00), stores it in srv-assets under the SRV Studio package, and
    records pkg.srvMusic. That record holds: song ID, version, prompt and lyrics hashes,
    who, when, regeneration count.
  - regenerate: capped per package (for example 3).
- MCP client: a small HTTP JSON-RPC client in lib/ (no new dependency or vendor).
- Usage ledger: srv_studio_v2_music_ledger, holding SRV Studio generations and downloads per
  month, with a warning before the shared 20 is reached.
Client:
- The Build stage panel built in 037 gains "Generate music". On select it loads the stored
  MP3 into the same place the drop zone uses (_srvAudioData), so Build is unchanged.
- The manual copy + drop-zone path stays as the fallback.
Unchanged: Build, Approve, Private Upload, Done, promotional Shorts, Monthly Mix, SRV Farsi.
Open design point: where the sealed token is stored.
- app_settings srv_studio_v2_* rows are publicly readable (ciphertext only).
- A private table is cleaner but is a protected shared-schema change needing CEO approval.
