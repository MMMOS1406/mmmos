WORK COMPLETED
1. Baseline and protection
   - Started from local 032 preview commit 0dc1386; its parent is production main c3a82a7.
   - New branch srv-studio/v2-033-mix-builder. Baseline failures were recorded on clean main
     before comparison.
2. Audio engine (lib/srvStudioV2MixAudio.mjs, new)
   - Measures true duration.
   - Trims lead silence at -50 dBFS (max 3 s) and trailing silence (max 8 s).
   - Long-soundtrack sources: also removes the Long's built-in 3 s fade-out, measured from
     the audio (fade start = first 400 ms window 1.5 dB under the preceding level), so joins
     never have a double fade. Original MP3s keep their own ending.
   - About 6 s equal-power crossfades (configurable).
   - Per-song BS.1770 loudness normalisation toward -14 LUFS, with boost capped at +9 dB to keep
     dynamics.
   - Look-ahead true-peak limiter: 5 ms look-ahead, 120 ms release, ceiling -2 dBTP before
     AAC so the delivered file stays at or below -1 dBTP.
   - 4x oversampled true-peak meter.
   - Rolling segment mixer, proven sample-identical to the one-shot reference mixer.
   - Audio is encoded once (MediaRecorder AAC). There are no intermediate encodes.
3. Audio sources
   - Uses the original Suno MP3 when it was retained (order 029), otherwise the Long video's
     AAC soundtrack.
   - The source used is recorded per track (original-mp3 / long-video-aac) and shown to the VA.
   - Order 029 retention verified: no existing Long has an MP3, because none was built
     after 029. Every new Long will.
   - The VA never downloads or supplies audio.
4. VA lifecycle (public/srv-studio-v2/srv2-mix.mjs, new; entry button in index.html)
   Generate Mix -> Select Songs -> Arrange & Preview -> Visual -> Metadata -> Build ->
   Approve -> Private Upload -> Done.
   - Month picker.
   - Server eligibility list showing title, duration, thumbnail, package, YouTube ID, visibility,
     audio source and the reason for any ineligible song.
   - "Suggest ~30 min" picks 5-8 songs.
   - Reorder, remove and replace.
   - Live total with transitions, chapter timestamps and transition preview through the real
     crossfade and limiter.
   - Draft save/restore on the server, with a local fallback.
   - Primary image chosen from the approved 19-image library.
   - Editable title, description and tags.
   - Build with progress, cancel and retry.
   - Approve; resumable upload; Done screen with release instructions, "I made it public",
     retry playlist and retry thumbnail.
   - Full-screen overlay outside #mainContent, so app re-renders cannot interrupt a build.
5. Mix renderer (dedicated path in srv2-mix.mjs)
   - 1920x1080 at 30 fps, H.264 + AAC.
   - Reuses the approved Long scene, grade, motion and thumbnail painter read-only.
     srv2-render.mjs is unchanged (test-enforced).
   - Accurate "Now Playing" chapter captions.
   - 1280x720 JPEG YouTube thumbnail with month badge.
   - Rolling decode: a song is prepared only when the previous segment starts playing,
     with at most 2 songs in memory.
   - Bitrate is planned from duration to stay at or under 500 MB.
   - Progress, cancel, error reporting and safe retry.
6. Mix package and data model (app_settings keys, no schema change)
   - srv_studio_v2_mix: config {enabled, channelId, playlistId|null, maxBytes}.
   - srv_studio_v2_mixes: mix records.
   - srv_studio_v2_mix_ledger: an isolated upload ledger.
   - Each record holds:
     - Identity: mixId (month plus ordered packages), monthKey, title.
     - Sources, ordered: package IDs, task IDs, YouTube IDs, titles, audio source,
       durations, trims, gains.
     - Timing: crossfade, chapter timestamps.
     - Content: image, description, tags.
     - Build and upload: render stats, output file (path, bytes, MIME, thumbnail), upload
       state, playlist.
     - Release: planned release slot, public confirmation.
     - History: audit trail (who, when, action).
   - Source Long packages are only read, never written (test-enforced).
   - The Long/Short ledger is untouched.
7. Private YouTube upload (server action srv_studio_v2_mix in api/ops.js; lib/srvStudioV2MixServer.mjs)
   - Access:
     - Requires a signed-in VA (operator) or CEO session.
     - Behind the publish gate, the V2 flag and the mix flag.
     - Exact SRV Studio connection with the channel ID verified.
   - Before upload:
     - The record is validated again.
     - Lineage is checked again at upload: every source must still be a public SRV Studio Long
       with the same YouTube ID.
     - The stored file's size and MIME type are checked against the record and the 500 MB limit.
   - Upload:
     - YouTube resumable session, PRIVATE, containsSyntheticMedia true, never publishAt.
     - The session URL is sealed with AES-256-GCM and never returned to the browser.
     - One 64 MiB chunk per server call (fits short function windows). Each call checks the
       confirmed offset first.
     - Retries cover resets and 5xx. An expired session is closed and restarted, with no
       duplicate video.
     - On completion the video is verified as SRV Studio and PRIVATE before it is recorded.
   - Duplicates: blocked by the record lock and by the ledger, one mix per month.
   - Browser to storage: Supabase TUS resumable upload in 6 MB chunks, resuming after interruptions.
8. Monthly scheduling
   - Last Saturday of the month, 2:00 PM America/New_York, with DST handled
     (EDT 18:00Z / EST 19:00Z).
   - Never collides with the Friday Long or Sunday Short slots.
   - Shown to the VA as a manual release instruction.
   - No automatic publishing and no publishAt.
   - "I made it public" records YouTube's real answer and marks the mix public only when the
     API confirms it.
9. Playlist
   - Mixes go to a playlist named "SRV Studio Mixes" via a configurable playlist ID, which is
     currently null, so the step shows "not configured" plus a manual step.
   - When configured: ownership is verified as SRV Studio, a duplicate add is skipped, and
     failures are recoverable with Retry playlist.
   - Other channels' playlists are never written.
   - The Long and Short playlists are unchanged.
   - No playlist was created.
10. Defects found and fixed during validation
   - The thumbnail was generated but not saved. It is now stored and set on the private video.
   - The Done screen could appear before the record reloaded.
   - A browser-tab crash came from pre-rendering all segments. The rolling feeder fixed it.
   - The encoded true peak reached -0.3 dBTP. The ceiling is now -2 dBTP before encode.
   - The fade trim was modelled instead of measured. It is now measured.
   - Edited titles were not restored with drafts.

REMAINING RISKS
1. Catalogue: only about 19 minutes of public music today. The first mix needs about 3 more
   public Longs.
2. The VA must keep the builder tab in front for about 31 minutes. Background tabs throttle
   rendering, so a warning is shown and recorded.
3. The browser downloads about 1.9 GB per mix while sources are Long soundtracks.
4. Mix size is about 475 MB, close to the 500 MB bucket limit. The bitrate is planned to stay
   under it, and longer mixes get a lower bitrate.
5. Pre-existing, not changed by 033:
   - The srv-assets bucket accepts anon writes to any path. The server re-checks size and
     path, but bucket hardening is a separate shared-system item.
   - The SMM rerender hook can clobber #mainContent. The builder avoids it via the overlay.
6. True-peak margin: the delivered AAC measured -1.0 dBTP in the final run and -1.4 in
   the previous run. Both meet the target of -1 dBTP or lower, but the final run is exactly at the
   limit, because the AAC encoder adds about 1 dB above the limiter's -2 dBTP. A -2.5 dBTP ceiling
   would give margin at the cost of 0.5 dB on peaks only. This is routine tuning, not a CEO item.
7. The real YouTube resumable endpoint and thumbnails.set have not been exercised live.
   That is by order, and covered by the acceptance test below.
